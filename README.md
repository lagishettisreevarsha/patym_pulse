# Paytm Business Pulse
> **Tagline:** From Payment Activity to Business Decisions  
> **Theme:** AI for Small Businesses (Paytm AI Hackathon 2026 – Hyderabad)

Paytm Business Pulse is an AI-powered decision-support layer for small merchants. Digital payment streams contain high-value business signals, but payment numbers alone do not tell merchants *what* is happening or *what* to do next.

This application acts as an analytics translator, addressing the core workflow:
**Business Activity → What Changed? → Why Does It Matter? → What Can I Do Next?**

---

## 📌 Project Overview & Problem Statement
Merchants notices sales fluctuations but struggle to answer:
1. **What changed?** (Detecting hidden anomalies, like an evening traffic slump or weekend surges).
2. **Why does it matter?** (Translating raw transactional statistics into a simple narrative).
3. **What should I focus on next?** (Providing actionable recommendations, e.g., target discounts, staffing shifts).

This tool calculates deterministic statistics in the backend first (averages, period-over-period changes, standard deviation outliers, peak hourly brackets) and then utilizes **Sarvam AI** to translate those signals into simple, understandable business advice.

## 🔌 Paytm Integration Adapter Status
We do not have confirmed production credentials for official Paytm merchant APIs. To avoid hardcoded stubs, the app implements a clean **Adapter Pattern**:
1. **`PaytmDataProvider`**: A TypeScript interface defining transaction queries, merchant summaries, and signals.
2. **`DemoPaytmDataProvider`**: Current active provider querying our PostgreSQL database seeded with 30 days of realistic Kirana transaction patterns.
3. **`RealPaytmDataProvider`**: Future provider that can be plugged in later to query live Paytm gateways without modifying any analytics or AI logic.

## 🛠️ Local Setup Instructions

### Environment Variables
Create `.env` inside the `backend/` folder:
```env
PORT=5000
NODE_ENV=development
DATABASE_URL="postgresql://postgres:1234@localhost:5433/paytm_business_pulse?schema=public"
SARVAM_API_KEY="your_sarvam_api_key_here" # Optional: App defaults to deterministic fallbacks if left blank
```

### Database Setup
1. Ensure PostgreSQL is running on `localhost:5433`.
2. Run database migrations:
   ```bash
   cd backend
   npx prisma migrate dev --name init
   ```

### Demo Data Setup
Seed the transaction history (1,110+ records with weekend surges, Wednesday sales spike, and evening drop shifts):
```bash
cd backend
npm run prisma:seed
```

### Running Backend Server
Start the Express server on port 5000:
```bash
cd backend
npm run dev
```

### Running Frontend Application
Start the Vite developer console on port 3000:
```bash
cd frontend
npm run dev
```

## 📊 API Documentation

### Merchant APIs
- **`GET /api/merchant/summary`**: Returns current KPIs, 7-day period comparisons, hourly trends, daily trends, payment ratios, and standard deviation anomalies.
- **`GET /api/merchant/transactions?page=1&limit=10`**: Returns paginated list of transactions.

### Business Pulse & AI APIs
- **`GET /api/business-pulse`**: Compiles analytics, requests a decision-support summary from Sarvam AI, logs the insight in the history ledger, and returns the narrative.
- **`POST /api/business-pulse/query`**: Answers natural language query grounded in metrics.
  - Body: `{ "question": "Why are my sales lower?" }`
- **`GET /api/business-pulse/history`**: Lists historical insights detected for the merchant.

### Demo APIs
- **`POST /api/demo/reset`**: Resets and re-seeds the PostgreSQL database with fresh transaction cycles.

## 🎭 3-Minute Hackathon Demo Flow
1. **Open Dashboard**: Show visual KPIs for "Karan Kirana Store". Highlight the `Demo Data Mode` banner.
2. **Deterministic Calculations**: Show the Hourly Checkout graph. Notice a visual slump in evening transactions.
3. **Hero AI Insight (What Changed?)**: Highlight the **Business Pulse** widget. See the header: *"Evening Store Footfall is Down"*.
4. **Why it Matters**: Read out the metrics-grounded breakdown generated by the LLM: *"Evening checkouts dropped 51% (46 checkouts vs typical baseline of 94)"*.
5. **Take Action**: Click *"Take Action"* on the card. View the pop-up containing promotional choices: *Happy Hour cashback deals between 6 PM - 9 PM* or *Kirana evening dinner combos*. Click activate to demonstrate operational loops.
6. **Query Assistant**: Go to the *"Ask Assistant"* page. Choose *"When are my busiest hours?"* or write a custom query. Receive a 3-sentence grounded answer referencing the exact database statistics.
7. **Reset Demo**: Click the circular reset arrows icon in the top header to reset the database transactions dynamically.
